# 🔐 权限管理

Mars 的权限很简单：**命名空间** 是访问控制的基本单位，角色也只有几个。

## 角色

| 角色 | 是谁 | 能做什么 |
|---|---|---|
| **管理员** | 平台的管理账号 | 所有命名空间、所有操作 |
| **创建者（owner）** | 创建命名空间的人 | 管理这个空间——转让、改公开/私有、同步成员 |
| **成员** | 被加进私有空间的人 | 在空间里部署和管理应用 |
| **登录用户** | 任何有效账号 | 使用公开空间、自己的文件 |

## 公开空间 vs 私有空间

- **公开** — 任何登录用户都能看到、能部署。适合共享的联调/演示环境。
- **私有** — 只有创建者和被添加的成员能访问。适合生产或敏感环境。

> 为保护隐私，没有权限的人看私有空间，会表现得像「不存在」一样。

## 每个操作需要什么权限

| 操作 | 谁能做 |
|---|---|
| 部署 / 升级应用 | 有该命名空间访问权的人（私有空间的成员也行）|
| 创建命名空间 | 任何登录用户 |
| 改成私有 / 转让 / 删除 / 同步成员 | 只有**创建者**（或管理员）|
| 开终端 / 看日志 | 有该命名空间访问权的人 |
| 下载自己的会话录屏 | 文件的所有者（或管理员）|
| 看全部审计事件 | 只有管理员——普通用户看自己的 |

## 管理你的团队

给某人开放一个私有空间：

1. 打开该命名空间。
2. 用 **同步成员** 把用户加进来。
3. 保存——他们就可以在里面部署和管理应用了。

要把空间交给别人，用 **转让**，所有权会转到对方名下。

## 给管理员的提示

- 内置 `admin` 账号绕过所有命名空间级检查。
- 部署 Mars 时注意两点：
  - **有命名空间访问权的人就能部署**（包括私有空间）。对高风险环境想要更严的控制，可以把部署权限收口到创建者或管理员。
  - **谁持有访问 token 谁就能用**（token 按「持有即有权」处理）。

需要配置公司登录？见 [系统配置 → 登录方式](./configuration.md#登录方式)。
